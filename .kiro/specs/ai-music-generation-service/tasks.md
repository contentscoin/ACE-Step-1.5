# 구현 계획: 멀티모달 AI 오디오 스튜디오 (MusicStudio)

## 개요

본 문서는 ACE-Step 1.5 생성 엔진 위에 곡·BGM·SFX·대사를 하나의 제품 표면에서 생성·편집·믹싱하는 멀티모달 AI 오디오 스튜디오의 구현 작업 목록이다. 백엔드는 TypeScript(Fastify) + Python(DSP Worker), 프런트엔드는 React 19 + Tailwind CSS 4 + Motion 12로 구현한다.

## 실행 순서 방침

- 각 Phase는 **하나의 변경 집합으로 몰아서 반영하지 않고, 독립적으로 리뷰 가능한 증분으로 분리해 순차 반영**한다. Phase 경계는 리뷰 단위 경계와 일치한다.
- **Phase 1은 완료되고 CI가 Green인 상태여야 Phase 2를 시작한다.** 특히 태스크 1.0의 import 경계 린트가 동작하지 않는 상태에서 후속 Phase의 코드를 작성하면 설계 §14 위험 #9(결합 축적)가 즉시 현실화되므로, 1.0은 Phase 1의 첫 커밋에 포함되어야 한다.
- Wave 내 태스크는 병렬 진행 가능하나, Wave N은 Wave 0..N-1이 모두 완료된 뒤 착수한다.

## Notes

- 백엔드 언어: TypeScript (Fastify) + Python (Celery DSP Worker)
- PBT 라이브러리: `fast-check` (TypeScript), `hypothesis` (Python)
- 각 태스크는 해당 요구사항과 설계 섹션을 참조하여 구현
- 참조 표기 규칙: `_Requirements:_`에는 요구사항 조항 번호만, `_설계:_`에는 설계 섹션 번호만 기재하며 두 줄로 분리한다
- 하나의 수용 기준 조항은 정확히 하나의 태스크가 구현 소유권을 갖는다. UI 태스크 7.3, PBT 감사 태스크 9.2, E2E 태스크 9.3의 참조는 구현 소유권이 아니라 검증 관점의 참조다
- 전체 테스트 스위트 Green 확인은 태스크 9.3의 수용 기준에서 수행한다(별도 Checkpoint 태스크 없음)
- 상업적 사용 전파는 고정 정책이며 어떤 설정으로도 우회 불가
- 결정적 재현을 위해 단일 스레드 BLAS, 동일 컨테이너 이미지 사용 필수
